NAME         top

axilio - Acquire and drive Axilio phones from the command line

SYNOPSIS         top

axilio [global options] <command> [command options]

DESCRIPTION         top

Acquire Axilio phones, drive live sessions, run workflows, and manage the resources that support them.

Start with login, acquire a session, observe its phone, then act on what is visible. Sessions remain active in Axilio until stopped. The CLI also saves session information locally so later phone commands can reconnect.

The main command families are:

phones / sessions   discover phones and manage active phone sessions
phone               observe and control the selected session's phone
workflows / runs    discover workflows and create or inspect runs
uploads             store media and deliver it to phones
api-keys            manage organization-scoped API keys

For detailed offline documentation, run man axilio. Run axilio help --html to print a clickable file:// URL for the browser-friendly version.

Resolution precedence and output-mode details are collected under NOTES.

COMMON WORKFLOW         top

A typical interactive session signs in, acquires a phone, observes it, performs an action, verifies the result, and releases the session:

axilio login
eval "$(axilio sessions start --export)"
axilio phone observe
axilio phone tap --query "the search box"
axilio phone observe
axilio sessions stop <session-id>

Use axilio sessions start --export with eval when separate shells or agents must pin different sessions through AXILIO_SESSION.

GLOBAL OPTIONS         top

  • --api-key=value - API key for API-backed commands; overrides AXILIO_API_KEY and the saved key
  • --base-url=value - API host for API-backed commands; overrides AXILIO_BASE_URL and saved base-url
  • --no-color - Disable ANSI color in human-oriented output
  • --org=value - OAuth organization slug or id; overrides AXILIO_ORG and the saved active org
  • -o, --output=value - Result format for runnable application commands: table or json; help, completion, and version stay text, and sessions start --export stays shell (default "table")
  • -q, --quiet - Suppress stderr notes and prompts; destructive commands still require --yes

api-keys

axilio api-keys

Manage API keys scoped to the active organization. List keys to discover their IDs, create a named key whose secret is shown once, or delete a key by ID. Organization access and API-key management permissions are enforced by the API.

Running axilio api-keys without a subcommand is equivalent to axilio api-keys --help: it only displays this help and does not list, create, or delete API keys. Global flags shown here therefore have no effect. Pass flags to an api-keys subcommand instead.

Global-option behavior

•
--api-key, --base-url, --no-color, --org, --output / -o, --quiet / -q - No effect on api-keys command; bare axilio api-keys only displays this help

Workflow examples

axilio api-keys list
axilio api-keys create ci
axilio api-keys delete key_123 --yes

list

axilio api-keys list

List API keys in the active organization.

Results include key ID, name, masked preview, last-used time, and creation time. Full secret values are never returned; use the ID with api-keys delete.

Global-option behavior

completion

axilio completion

Generate a shell completion script for axilio.

After installing the generated completion script, users can type:

axilio api-<Tab>
axilio phone <Tab>
axilio sessions start --<Tab>

Their shell can complete command names, subcommands, and flags, reducing typos and making the command tree easier to discover. Completion is currently limited to this static command metadata; Axilio resource IDs and names are not fetched dynamically.

Choose bash, zsh, fish, or powershell. The generated script is written to stdout so it can be sourced for the current shell or redirected to that shell's completion directory.

Workflow examples

source <(axilio completion bash)
axilio completion zsh > "${fpath[1]}/_axilio"
axilio completion fish > ~/.config/fish/completions/axilio.fish
axilio completion powershell | Out-String | Invoke-Expression

config

axilio config

Inspect and edit CLI configuration without hand-editing files. Bare axilio config reports the effective API host, API-key authentication summary, active organization, config path, and sessions directory. The current summary does not detect a stored OAuth session, so an OAuth-only login may be shown as auth method none; status verifies effective credentials. The only editable key is base-url.

Current ways to change these values are:

API host         axilio config set base-url [url]
                 axilio config unset base-url
API key          axilio login --api-key [api_key]
                 axilio logout clears saved credentials
Active org       axilio orgs use [org_name]
                 axilio orgs clear
Config path      set XDG_CONFIG_HOME; file is [value]/axilio/config.json
                 (default ~/.config/axilio/config.json)
Sessions dir     set XDG_CONFIG_HOME; directory is [value]/axilio/sessions
                 (default ~/.config/axilio/sessions)

Global-option behavior

  • --api-key=value - Temporarily shows this as the effective API key source; does not save the new key. Use axilio login --api-key [api_key] to verify and persist a new key.
  • --base-url=value - Temporarily shows this as the effective API host; does not save the new host. See the above help content to change base-url.
  • --no-color - Disable ANSI color in the human-readable configuration table
  • --org=value - Temporarily changes the displayed organization; does not save the selection. Use axilio orgs use [org_name] instead to persist changes to active org setting.
  • -o, --output=value - Render the configuration summary as table or json (default "table")
  • -q, --quiet - Suppress stderr update notices; the configuration summary remains on stdout

Examples and expected output

Sample 1

user@host ~ % axilio config
API host     https://api.axilio.ai
Auth method  api-key (source: config)
Active org   (session default)
Config file  <config-path>
Sessions dir <sessions-directory>

# Exit status: 0

Sample 2

user@host ~ % axilio config set base-url https://api.axilio.ai

# Standard error:
Set base-url = https://api.axilio.ai in <config-path>

# Exit status: 0

Sample 3

user@host ~ % axilio config unset base-url

# Standard error:
Unset base-url in <config-path>

# Exit status: 0

init

axilio init [flags]

Write an instruction file that teaches your coding agent to drive a phone through the axilio CLI and then hand back a runnable Python or Go script using the Axilio SDK. The agent asks whether you want Python or Go.

Bare axilio init detects which agents this repo uses (.claude/, AGENTS.md, .cursor/) and writes a skill for each; on a terminal with nothing detected it asks. --agent picks one explicitly:

--agent claude  ->  .claude/skills/axilio/SKILL.md
--agent codex   ->  AGENTS.md (appended, never clobbered)
--agent cursor  ->  .cursor/rules/axilio.mdc

Auto-detected targets that already contain the skill are skipped. An explicit target that already exists is an error unless --force is set; for AGENTS.md, --force replaces only the marked Axilio block. Without markers, interactive mode asks which agent to configure, while JSON, quiet, or redirected use requires --agent.

It finishes with a sign-in check: browser login is the one step an agent can't do itself, so init surfaces it while a human is likely at the keyboard.

Command options

  • --agent=value - Target claude, codex, or cursor; omit to detect repository markers
  • --force - Refresh an existing skill; only the marked Axilio AGENTS.md block is replaced

Global-option behavior

  • --api-key, --org - No effect on init command
  • --base-url=value - Host for the skill download and sign-in check; overrides AXILIO_BASE_URL and saved base-url
  • --no-color - Disable ANSI color in init success messages
  • -o, --output=value - Emit human init messages or JSON written and skipped path lists (default "table")
  • -q, --quiet - Suppress human init prompts and messages; --agent may be required; JSON still prints

Examples and expected output

Sample 1

# Standard error:

login

list

axilio workflows list [flags]

List workflows in the active organization, most recent first.

Results include workflow ID, name, platform, status, and last-run time. Use --search for a name substring and --limit to control the number returned. A listed workflow ID can be passed directly to runs start.

Command options

  • --limit=number - Maximum number of most-recent workflows to return (default "20")
  • --search=value - Filter workflow names by substring

Global-option behavior

  • --api-key=value - API key for the workflow-list request; overrides AXILIO_API_KEY and the saved key
  • --base-url=value - API host for the workflow-list request; overrides AXILIO_BASE_URL and saved base-url
  • --no-color - Disable ANSI color in the human-readable form of the workflow-list result
  • --org=value - OAuth org for the workflow-list request; overrides AXILIO_ORG and the saved active org; API keys ignore it
  • -o, --output=value - Render the workflow-list result as table or json (default "table")
  • -q, --quiet - Suppress stderr notes for the workflow-list request; the workflow-list result remains on stdout

NOTES         top

Resolution precedence

Credentials resolve in this order: --api-key, AXILIO_API_KEY, the saved config API key, then the saved OAuth session.

The organization resolves from --org, AXILIO_ORG, the saved active organization, then the OAuth session default. Note that each API key is scoped to the organization that created it and cannot switch organizations with --org.

API host resolves from --base-url, AXILIO_BASE_URL, saved base-url, then https://api.axilio.ai.

Phone command session selection precedence is --session, AXILIO_SESSION, the only locally saved session, the most recently started session, then an ambiguity error.

Output behavior

Table output for human readability is the default. Every successful runnable application command emits valid JSON with -o json; action commands return a small acknowledgment. Built-in help, completion, and version output remains text. The sessions start --export command emits shell text for eval. Notes, prompts, and progress use stderr and are suppressed in JSON or quiet mode. Quiet and JSON modes do not confirm destructive actions; pass --yes where offered. API-key, base-URL, and organization flags affect API-backed commands; they do not select a local phone session.

Error presentation

Error examples show the message text without terminal formatting. Actual error output may include an ERROR heading, spacing, and ANSI color.
