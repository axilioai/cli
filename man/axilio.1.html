NAME         top

axilio - Acquire and drive Axilio phones from the command line

SYNOPSIS         top

axilio [global options] <command> [command options]

DESCRIPTION         top

Acquire Axilio phones, drive live sessions, run workflows, and manage the resources that support them.

Start with login, acquire a session, observe its phone, then act on what is visible. Sessions persist locally until stopped.

The main command families are:

phones / sessions   discover phones and manage interactive leases
phone               observe and control the selected session's phone
workflows / runs    discover workflows and create or inspect runs
uploads             store media and deliver it to phones
api-keys            manage organization-scoped API keys

Resolution precedence and output-mode details are collected under NOTES.

COMMON WORKFLOW         top

A typical interactive session signs in, acquires a phone, observes it, performs an action, verifies the result, and releases the session:

axilio login
eval "$(axilio sessions start --export)"
axilio phone observe
axilio phone tap --query "the search box"
axilio phone observe
axilio sessions stop <session-id>

Use axilio sessions start --export with eval when separate shells or agents must pin different sessions through AXILIO_SESSION.

GLOBAL OPTIONS         top

  • --api-key=value - API key for API-backed commands; overrides AXILIO_API_KEY and the saved key

  • --base-url=value - API host for API-backed commands; overrides AXILIO_BASE_URL and saved base-url

  • --no-color - Disable ANSI color in human-oriented output

  • --org=value - OAuth organization slug or id; overrides AXILIO_ORG and the saved active org

  • -o, --output=value - Result format for runnable application commands: table or json; help, completion, and version stay text, and sessions start --export stays shell (default "table")

  • -q, --quiet - Suppress stderr notes and prompts; destructive commands still require --yes

config

axilio config

Inspect and edit CLI configuration without hand-editing files. Bare axilio config reports the effective API host, API-key authentication summary, active organization, config path, and sessions directory. The current summary does not detect a stored OAuth session, so an OAuth-only login may be shown as auth method none; status verifies effective credentials. The only editable key is base-url.

Current ways to change these values are:

API host         axilio config set base-url [url]
                 axilio config unset base-url
API key          axilio login --api-key [api_key]
                 axilio logout clears saved credentials
Active org       axilio orgs use [org_name]
                 axilio orgs clear
Config path      set XDG_CONFIG_HOME; file is [value]/axilio/config.json
                 (default ~/.config/axilio/config.json)
Sessions dir     set XDG_CONFIG_HOME; directory is [value]/axilio/sessions
                 (default ~/.config/axilio/sessions)

Global-option behavior

  • --api-key=value - No actual effect. Ephemerally shows this as the effective API key source; does not persist the new key. Use axilio login --api-key [api_key] to verify and persist a new key.

  • --base-url=value - No actual effect. Ephemerally shows this as the effective API host; does not save the new host. See the above help content to change base-url.

  • --no-color - Disable ANSI color in the human-readable configuration table

  • --org=value - No actual effect. Ephemerally changes the displayed org only, does not save the selection. Use axilio orgs use [org_name] instead to persist changes to active org setting.

  • -o, --output=value - Render the configuration summary as table or json (default "table")

  • -q, --quiet - Suppress stderr update notices; the configuration summary remains on stdout

init

axilio init [flags]

Write an instruction file that teaches your coding agent to drive a phone through the axilio CLI and then hand back a runnable SDK script. The agent asks whether you want Python or Go.

Bare axilio init detects which agents this repo uses (.claude/, AGENTS.md, .cursor/) and writes a skill for each; on a terminal with nothing detected it asks. --agent picks one explicitly:

--agent claude -> .claude/skills/axilio/SKILL.md

--agent codex   ->  AGENTS.md (appended, never clobbered)
--agent cursor  ->  .cursor/rules/axilio.mdc

Auto-detected targets that already contain the skill are skipped. An explicit target that already exists is an error unless --force is set; for AGENTS.md, --force replaces only the marked Axilio block. Without markers, interactive mode asks which agent to configure, while JSON, quiet, or redirected use requires --agent.

It finishes with a sign-in check: browser login is the one step an agent can't do itself, so init surfaces it while a human is likely at the keyboard.

Command options

  • --agent=value - Target claude, codex, or cursor; omit to detect repository markers

  • --force - Refresh an existing skill; only the marked Axilio AGENTS.md block is replaced

Global-option behavior

  • --api-key=value - No effect on init command. A supplied value only changes the final sign-in message

  • --base-url=value - Host for the skill download and sign-in check; overrides AXILIO_BASE_URL and saved base-url

  • --no-color - Disable ANSI color in init success messages

  • --org=value - No effect on init command. Skill download and generated files are not org-scoped

  • -o, --output=value - Emit human init messages or JSON written and skipped path lists (default "table")

  • -q, --quiet - Suppress human init prompts and messages; --agent may be required; JSON still prints

logout

axilio logout

Sign out locally and, when present, revoke the OAuth refresh-token family server-side.

The saved API key, OAuth session, and active organization are removed. A saved base URL, environment credentials, and local phone-session lease files are not removed.

Global-option behavior

NOTES         top

Resolution precedence

Credentials resolve in this order: --api-key, AXILIO_API_KEY, the saved config API key, then the saved OAuth session.

The organization resolves from --org, AXILIO_ORG, the saved active organization, then the OAuth session default. Note that each API key is scoped to the organization that created it and cannot switch organizations with --org.

API host resolves from --base-url, AXILIO_BASE_URL, saved base-url, then https://api.axilio.ai.

Phone command session selection precedence is --session, AXILIO_SESSION, the sole active lease, the saved current-session pointer, then an ambiguity error.

Output behavior

Table output for human readability is the default. Every successful runnable application command emits valid JSON with -o json; action commands return a small acknowledgment. Built-in help, completion, and version output remains text. The sessions start --export command emits shell text for eval. Notes, prompts, and progress use stderr and are suppressed in JSON or quiet mode. Quiet and JSON modes do not confirm destructive actions; pass --yes where offered. API-key, base-URL, and organization flags affect API-backed commands; they do not select a local phone session.
